Rule examples

Rules that work together.

One rule moves one kind of mail. These recipes combine them: shared lists, senders your provider vouches for, tags that later rules route on, and actions that wait. Every key is in the rules reference.

Hold new mail for your phone Move only verified finance mail Keep security alerts out of the automated pile File work mail, minus its bots Mark mail from outside the team Delete CI mail once seen Keep overdue invoices in view Tidy a folder that is not INBOX

Order matters. Rules run in file order, top to bottom, on every sync. The recipes are written in the order they would sit in one rules.toml, so the stop in an early rule decides what the later ones see. Replace the .example domains and addresses, the account name and the folder names with your own.

Hold new mail for your phone

Mail apps on a phone mostly notify only for INBOX. Put this rule first and nothing below it touches a message for its first 15 minutes, so the phone sees everything before it is sorted.

It also delays rules that only tag or mark read. To delay only the moves, give each moving rule its own after instead, as in Delete CI mail once seen.

rules.toml
[[rules]]
name = "hold new mail for the phone"
match.younger_than = "15min"
actions.stop = true

Move only verified finance mail

Anyone can write paypal.com in a From line. authenticated holds only when your provider checked the signatures that prove a message came from that domain (DKIM and DMARC). Real bank mail is filed, and a lookalike stays in the inbox, flagged. One [lists] entry feeds both rules.

Needs the account's trusted_authserv_ids. Without it no mail counts as authenticated, so the second rule flags all of it. The tag needs a server that accepts custom keywords.

rules.toml
[lists]
finance = ["bank.example", "paypal.com"]

[[rules]]
name = "finance, verified"
match.from_domain = { list = "finance" }
match.authenticated = true
actions.move = "Finance"
actions.stop = true

[[rules]]
name = "finance lookalikes"
match.from_domain = { list = "finance" }
match.authenticated = false
actions.tag = "$Suspicious"
actions.flagged = true
actions.stop = true

Keep security alerts out of the automated pile

Tag in one rule, route on the tag in the next: a rule sees what the rules above it changed in the same sync. The first rule tags and flags security alerts. The second clears mail from no-reply addresses out of the inbox, except what the first one tagged, so a sign-in alert from a no-reply address stays where you will see it.

Tags are IMAP keywords, which Thunderbird and other clients show as tags. They start with $ here, a common convention for keywords; any name without spaces works.

Needs a server that accepts custom keywords.

rules.toml
[lists]
bots = { regex = "no-?reply|notifications?@" }
security_subjects = { regex = "sign-?in alert|new device" }

[[rules]]
name = "tag security alerts"
match.subject = { list = "security_subjects" }
actions.tag = "$Security"
actions.flagged = true

[[rules]]
name = "automated mail out of the inbox"
match.from = { list = "bots" }
match.none = [{ tag = "$Security" }]
actions.move = "Automated"
actions.notify = false

File work mail, minus its bots

Nest none inside any: each entry of any is a set of conditions that must all hold, and can exclude mail of its own. This files mail from colleagues, but not their build bots, together with anything sent to your work alias. It reuses the bots list from the recipe above.

rules.toml
[[rules]]
name = "work, minus the robots"
match.any = [
  { from_domain = "work.example", none = [{ from = { list = "bots" } }] },
  { alias = "me+work@example.com" },
]
actions.move = "Work"

Mark mail from outside the team

to_domain reads the To header, from_domain the sender's address and never the display name. Together they tag mail sent to your company from anywhere else.

Needs a server that accepts custom keywords.

rules.toml
[[rules]]
name = "tag external mail to the team"
match.to_domain = "work.example"
match.none = [{ from_domain = "work.example" }]
actions.tag = "$External"

Delete CI mail once seen

GitHub marks its build mail with an X-GitHub-Reason header. after takes a list and waits for whichever comes first: you read the message, or two days pass. A delete keeps an .eml copy in Postvak's trash, so postvak trash restore brings it back.

rules.toml
[[rules]]
name = "CI mail, once seen"
match.header.X-GitHub-Reason = { equals = "ci_activity" }
actions.delete = true
actions.after = ["read", "2d"]

Keep overdue invoices in view

Archive invoices, except reminders, whether the reminder is in the subject or only in the text. HTML mail is converted to text before the body regex reads it.

Needs the body of new mail in the rule's folder, which Postvak downloads for this rule. A message whose body could not be downloaded never matches, even through none, so it stays in the inbox.

rules.toml
[[rules]]
name = "overdue invoices stay put"
match.subject = { contains = ["invoice", "factuur"] }
match.none = [
  { subject = { contains = ["overdue", "reminder"] } },
  { body = { regex = "payment (is )?overdue" } },
]
actions.archive = true

Tidy a folder that is not INBOX

A rule watches INBOX unless it names a folder, and runs for every account unless it names one. This one archives list mail you have read, two weeks on, for your personal account only, and leaves flagged threads alone.

rules.toml
[[rules]]
name = "tidy Lists"
account = "personal"
folder = "Lists"
match.read = true
match.flagged = false
match.older_than = "2w"
actions.archive = true

Try them before they act

A new rule acts only on mail that arrives after you enable it. Before that, check the file and preview each rule on the mail Postvak has cached. --as-of moves the clock, to see what older_than and after will do later, and rules coverage shows mail that several rules compete for. The rules reference has more examples of single rules.

$ postvak rules check
$ postvak rules test "tag security alerts"
$ postvak rules test --as-of 2d
$ postvak rules coverage --folder INBOX
